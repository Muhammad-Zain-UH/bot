## 1. `2026-09-16_signal_log_legacy_mixed_schema.csv`

| | |
|---|---|
| **Was** | `signal_log.csv` (repository root) |
| **How moved** | `git mv` — git history preserved |
| **Size** | 10,782,636 bytes · 39,710 lines |
| **Status** | **STRUCTURALLY CORRUPT — NOT PARSEABLE AS A DATASET** |

### Why it was archived

The file carries a **77-column header** belonging to an earlier, now-abandoned
pipeline (`utils/result_writer.py` + `ai_analyst.py`):

```
timestamp,symbol,session,signal,setup_direction,entry_timing_state,confidence,
weighted_score,risk_level,ai_used,news_sentiment_score,...,wyckoff_phase,...,
outcome,actual_exit_price,actual_pnl_pips
```

The code that actually wrote the rows — `main_production.log_signal()` — emits a
**different 21-column schema**. Because `csv.DictWriter` only writes a header when
the target file does not yet exist, the stale header was never replaced.

**Consequence:** column *N* in the header does not describe column *N* in the data.
Reading it with any header-aware CSV reader yields silently mislabelled fields —
e.g. the column labelled `symbol` actually contains `signal_type`.

### What the data does and does not contain

- 39,709 data rows, **all** with `signal_type == PRE_ENTRY`
- **0 rows** with `signal_type == ENTRY_SIGNAL`

No entry signal was ever recorded. This file therefore contains **no trade
outcomes, no P&L, and no fills** — only rejected-setup diagnostics.

### Explicitly NOT done

Per Phase 0 instructions, **no attempt was made to reconstruct trades from this
file.** Re-aligning the columns would require guessing which writer produced which
row, and any result would be fabricated data. It is preserved as-is for forensic
purposes only.

## 2. `2026-09-16_active_trades_phantom.json` · `2026-09-16_active_trades_backup_phantom.json`

| | |
|---|---|
| **Were** | `trade_states/active_trades.json`, `trade_states/active_trades_backup.json` |
| **How copied** | `cp` — originals then **reset to an empty trade list** |
| **Status** | **CONFIRMED NOT REAL BROKER POSITIONS** |

### Contents

```
XAUUSD_001  BUY   entry 2450.0  SL 2420.0  TP 2540.0  entry_time 2026-05-27T10:00:00
XAUUSD_002  SELL  entry 2460.0  SL 2430.0  TP 2550.0  entry_time 2026-05-27T11:30:00
```

### Evidence these were not real positions

1. **Prices are impossible for the recorded period.** Both are priced at ~2450–2460.
   The production log shows XAUUSD trading at **3982–4066** throughout the logged
   window. A position opened at 2450 could not exist alongside those quotes.
2. **`mt5.order_send()` is never called on any opening path.** It appears only in
   the shutdown routines of `main.py` and `main_production.py`. No order was ever
   transmitted to a broker.
3. **The execution path is a guaranteed no-op.** `main_production.py` calls
   `order_executor.execute_order(order_id, mt5_handler=None, simulation=False)`;
   `order_execution.py` returns `(False, "No MT5 handler provided and simulation
   disabled")` for exactly that combination.
4. **`order_id` fields are synthetic.** Values such as
   `XAUUSD_001_auto_1781845161` were generated by the `[AUTO_FIX]` branch in
   `manage_positions()`, not by any broker.
5. **Values match `order_execution.py`'s own `__main__` demo block**, which creates
   a test order at `entry_price=2450.00, stop_loss=2420.00, take_profit=2540.00`.

### Operational harm they were causing

`restore_state()` loaded both on every start. They counted against
`CONFIG["max_concurrent_trades"] = 3`, leaving one usable slot, and could never be
cleared: their `order_id`s do not exist in `OrderExecutor.orders`, so
`update_current_price()` returned `{"status": "error"}` indefinitely.

## 3. `2026-09-16_closed_trades_UNVERIFIED_SUSPECTED_SYNTHETIC.json`

| | |
|---|---|
| **Is a copy of** | `trade_states/closed_trades.json` |
| **How copied** | `cp` — **the original was NOT modified, NOT reset, NOT deleted** |
| **Status** | **UNVERIFIED / SUSPECTED SYNTHETIC** |

### Contents

```
XAUUSD_001  entry 2450.0 → exit 2540.0   pnl 90.0   pnl_pct 0.36   RR 3.0
closed_at 2026-05-27T16:21:36
```

### Why it is *suspected* synthetic

- Shares `trade_id` **`XAUUSD_001`** with the confirmed-phantom active position.
- Entry `2450.0` and exit `2540.0` correspond exactly to the phantom position's
  entry and take-profit — i.e. a textbook "TP hit" with no slippage.
- `signal_log.csv` contains **0** `ENTRY_SIGNAL` rows across 39,709 decisions, so
  no entry signal was ever produced that could have opened it.
- No opening `order_send` path exists anywhere in the codebase.
- The same three numbers appear in `order_execution.py`'s `__main__` demo block.

### Why it has NOT been removed

**This is treated as financial/trading history and is preserved.** The evidence
above is strong but circumstantial: this audit reconstructed system behaviour from
source and logs, not from broker statements. A definitive determination requires
broker-side reconciliation against MT5 deal history, which does not exist yet.

**A final ruling is deferred to the Phase 2 ledger / reconciliation work.** Until
then this record is classified `UNVERIFIED / SUSPECTED SYNTHETIC` and must not be
treated as a real trade for any performance, risk, or statistical purpose.

## 4. Note on `trading_bot_production.log`

Not archived; left in place. Two facts are recorded here for the record:

1. **The log contains test output.** Four `[ENTRY] ENTRY SIGNAL GENERATED` entries
   (2026-07-01 15:20, 15:53; 2026-07-02 09:23, 09:59) showing `Entry: 101.00 /
   SL: 99.00 / TP: 104.00` are **unit-test fixtures** from
   `tests/test_layer_gate_logic.py`, not real signals. They entered the production
   log because `main_production` builds its `FileHandler` at import time against a
   hardcoded path, so merely importing the module under test writes to it.
   Phase 0.4 fixes this. **The bot has never generated a real entry signal.**

2. **The Phase 0 baseline test run added two more lines.** Before establishing the
   baseline the log was 17,058,427 bytes / 67,974 lines; afterwards 17,058,829
   bytes / 67,976 lines. The two added `[DECISION]` lines (`price=N/A`,
   `regime=REGIME_SCALP`) are test output from `tests/test_production_log_output.py`.
   This was the final pollution event; test logging is isolated from Phase 0.4 onward.

The log has no rotation and is recorded in `PHASE_2_ISSUES.md` for follow-up.
